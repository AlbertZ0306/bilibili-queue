## 安装或更新

1. 将 ZIP 解压到独立文件夹，例如 `bilibili-queue`。打开该文件夹应直接看到 `manifest.json`；加载时就选择这个文件夹。安装包中的 manifest 已放在 ZIP 根目录。
2. 打开 `chrome://extensions/`，开启开发者模式，加载已解压的扩展程序。
3. 已安装旧版时，将新文件覆盖到原来的文件夹，再点击扩展的重新加载。使用原文件夹可保留本地列表和设置。

## 使用

在 B 站视频页点击标题后的「加入播放列表」，然后可在扩展弹窗查看新增条目。更新扩展后请刷新已经打开的 B 站视频页。

点击右上角添加视频，在弹窗中粘贴，例如：

```text
BV1xx411c7mD
https://www.bilibili.com/video/BV1Q541167Qg/
https://www.bilibili.com/video/BV1ai4y1N7SV/?p=2
```

每行一条，也可使用空格、逗号、分号分隔。Ctrl+Enter 可提交。失败条目会保留，关闭后重新编辑的草稿不会被旧请求覆盖。

选择顺序或逆序后，点击底部粉色播放按钮：停止时从所选方向的起点开始，播放时该按钮为重播当前。每行的播放按钮可从该条开始，之后按当前方向继续。暂停或恢复当前视频仍可直接操作 B 站播放器。

- 上一条／下一条遵循所选方向，非循环边界按钮禁用。
- 停止会暂停播放器并结束队列运行；关闭管理界面不影响队列播放。
- 播放中调整方向或拖动排序，当前视频继续播放，下一条按新设置选择。
- 在列表工具栏的「倍速」中选择 1×、1.5×、2× 或 3×。设置保存在本机，清空列表也保留；仅控制插件正在管理的播放页。播放器重置速度或更换 video 节点时会重新应用。
- 不带 p 参数时只播放第 1 P；带 p 时只播放对应 P，不会自动展开整部多 P 视频。
- 标题、分 P 时长和封面自动获取；信息接口失败会回退到公开视频网页。旧列表会尝试补齐封面，失败时显示占位图。可使用刷新按钮重试。
- 总时长按列表中所有条目计入，重复条目分别计算，分 P 使用对应 P 的时长。
- 时长、已播时间和进度继续按视频原始时间显示；倍速不会改变标注的总时长。

## 进度与异常

视频已播时间、实际时长和百分比约每秒同步。列表进度按当前排列和方向中的位置计算，前置位置视为已走过；它不是累计实际观看时间。跳过、重排或变更方向会重新计算。未知时长会明确显示，并按条数估算整体比例。

首次有声自动播放可能需要在 B 站页面点击播放。登录、会员、地区、下架等限制仍由 B 站决定。无法观看、加载失败或卡住的条目不会自动跳过，请检查播放页或手动切换。自动检测面向 HTML5 video 播放器。

手动离开当前播放页或关闭标签页会停止队列。浏览器重启后列表保留，但需要手动重新开始。更新扩展后也建议重新开始一次播放。

## 权限与数据

权限保持为 storage 和三个站点：www.bilibili.com、b23.tv、api.bilibili.com。没有新增浏览器权限，没有远程框架脚本或统计服务。

列表、方向和倍速设置保存在本机；实时播放状态保存在浏览器会话存储。添加或刷新时，BV 号会发送到 B 站信息接口；接口失败时会访问该视频的公开网页并读取内嵌 JSON，不执行网页脚本。信息请求不携带 Cookie。短链会访问 b23.tv。封面由 B 站图片 CDN hdslb.com 直接加载，图片请求不附带来源页 Referer；无效或无法加载的封面使用占位图。

同批重复短链共用请求，解析最多并发 4 条、单条最长 8 秒、整批预算 20 秒；视频信息最多并发 3 条。清空会使未提交的旧导入失效。卸载会删除本地列表；当前没有导出功能。

## 开发

项目仓库：https://github.com/AlbertZ0306/bilibili-queue 。从 GitHub 获取时可执行：

```sh
git clone https://github.com/AlbertZ0306/bilibili-queue.git
cd bilibili-queue
```

仓库同时保留源码和可直接加载的生产文件。日常修改后执行构建和测试，再使用 `git add`、`git commit`、`git push` 保存并上传变更。依赖、临时测试数据、密钥和 ZIP 安装包由 `.gitignore` 排除；安装包存放在项目目录之外。

`popup.js` 是已编译的生产包，不要直接编辑。界面源码位于 `src/popup.jsx`，样式位于 `popup.css`。播放后台、内容脚本和数据模块保持独立 ES 模块。

```sh
npm install
npm run build
npm test
```

React、React DOM 和 Scheduler 的完整许可证保存在 `THIRD_PARTY_NOTICES.md`，编译注释见 `popup.js.LEGAL.txt`；构建依赖只用于开发，用户安装扩展不需要运行 npm。

浏览器专项测试另需安装 Playwright：

```sh
npm install --no-save playwright
npx playwright install chromium
node tests/browser-audit.cjs
node tests/playback-rate.cjs
node tests/metadata-fallback.cjs
node tests/quick-add.cjs
node tests/playlist-copy.cjs
```

原生工具栏弹窗尺寸回归（会短暂打开独立测试浏览器窗口）：

```sh
node tests/native-popup.cjs
```

此测试关闭 Playwright 的 viewport 模拟，使用真正的 headed Chromium 工具栏弹窗，并要求 Chrome 返回 `POPUP` 上下文；尺寸不正确即失败。`NATIVE_SCALE=1` 可测试 100% 缩放，`NATIVE_SCREENSHOT` 可指定截图路径。

它使用独立临时浏览器配置和模拟服务，不访问个人浏览器会话。可用 BILI_TEST_BROWSER 指定测试浏览器，用 BILI_AUDIT_WORKDIR 指定临时配置目录。
